# Complete functional inventory — local-first review

**Review date:** 8 November 2026 (final interactive audit update)  
**Scope:** current repository source, Prisma schema and migration files, storefront/admin routes and server actions, components, all 15 original Stitch screen exports (screenshots and `code.html` inventories), project docs, and available Vitest/Playwright suites. Stitch files are reference material only; customer-account screens are superseded by the owner decision that customers check out as guests. Hosting/provider/deployment work is excluded. No code was changed while compiling this inventory.

## Classification

- **A — Complete and verified:** behavior exercised end-to-end and supported by current tests/evidence.
- **B — Implemented but incomplete:** a working base exists, but a specifically required path or coverage is missing.
- **C — Implemented but broken:** reproducible defect in an existing workflow.
- **D — Missing:** required behavior has no implementation.
- **E — Requires owner decision:** business copy, contacts, terms, or workflow cannot be safely invented.
- **F — Requires professional optical approval:** clinical/optical decision must come from a qualified professional.
- **G — Hosting-dependent and deferred:** requires external hosted infrastructure/provider, intentionally out of scope.

“Verified” below means evidence from current tests or current route/action behavior reviewed. The 8 November final interactive audit and exact regression outcomes are recorded in [`COMPLETE_FINAL_FUNCTIONAL_AUDIT.md`](COMPLETE_FINAL_FUNCTIONAL_AUDIT.md). Historical result counts below are superseded by that report where noted.

## Confirmed work items and implementation progress

1. **P0:** Re-run guest checkout/cart/outbox critical flows in isolated synthetic schemas and fix only reproducible regressions.
2. **P1 — Implemented and verified:** the lens configurator now requests the exact decision from the authoritative server evaluator and displays approved/incompatible/pending status with explicit professional-review caveat. The owner rules list now supports status filter, search, and pagination across all recorded rules rather than truncating at the latest 100. Unit suite, focused optical browser test, and full acceptance passed. No compatibility decision was created or changed by this work.
3. **P2 — Investigated:** newsletter action only stores the address; no campaign delivery or unsubscribe implementation exists although homepage copy claims a 10% incentive and one-click unsubscribe. These are not safe to fabricate or activate; classify as **E (owner/business approval)** pending a decision on actual marketing operation, consent, unsubscribe mechanism and benefit. No copy/value is being silently invented.
4. **P2 — Implemented partly; browser verification pending:** homepage optical option labels/prices now use current active database options; arbitrary active coupons are no longer presented as a homepage promotion unless the owner publishes a promotion banner. The trust claims, warranty/delivery/insurance claims and some category visuals remain hard-coded. Actual owner-configured values exist elsewhere, but specific storefront claims cannot be rewritten without owner approval. This is a CMS completeness/content-approval gap, not hosting work.
5. Local product image upload/publication passed acceptance. Valid prescription upload/retrieval remains unverified because the seeded exact optical combination is pending and correctly blocked; do not forge approval to test around the gate. Reconcile historical documents with actual implementation and record remaining owner/professional blockers explicitly.
